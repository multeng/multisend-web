# Recipient preparation: stage2A

## Intent and agreed approach

Build the next block of PLAN.md: prepare native TON testnet recipients without sending. The owner already chose mobile variant B after browser mockups: a list of cards with inline amount editing and a details form, desktop columns over the same state. Their instruction to continue the plan authorizes implementation of this selected approach. A rich text CSV editor was considered earlier; structured fields preserve precise strings and identify per-row errors more clearly. A spreadsheet grid alone does not fit the chosen phone-first workflow. Keep React/Radix/CSS Modules and existing APIs.

## Behavior

- Anonymous preparation is memory-only, never uploaded or persisted in browser storage. Explicit CSV export lets users keep unfinished input. Authentication changes never copy private recipients into the anonymous editor. Public editor state remains separate from private drafts.
- Fields remain address/amount/comment strings matching DraftRecipient. Max200 recipients,128 code points per address/amount,500 per comment. No silent truncation on import. Amounts: ASCII decimal dot, up to9 fractional digits, strictly positive, no exponent/separators/signs/whitespace, below2^120 nanotons. BigInt arithmetic and decimal formatting only. Empty/intermediate input remains editable and saveable as draft.
- Support raw workchain0/-1 with exactly64 hex digits, and48-character base64/base64url user-friendly addresses, flags and CRC16 per TEP2. Normalize only for duplicate comparisons, never rewrite original input. Testnet-only friendly addresses accepted. Standard friendly addresses without test flag and raw addresses have no assertion of network exclusivity: show a warning, not an invented network claim. No DNS or nonstandard workchains in this block. Non-bounceable and bounceable forms count as duplicates.
- Row errors identify invalid address, amount, comment length. Repeated canonical address is a warning and needs an explicit acknowledgement before preview; never merge payments. Editing any field or structure resets acknowledgement and closes preview. Warn that syntax does not prove address ownership, activation or recipient identity.
- Add row, edit address/comment in an accessible Radix Dialog, inline decimal amount, remove row with confirmation. Stable client-only IDs preserve focus. Desktop uses aligned columns, mobile cards; no horizontal scrolling at360px. Buttons have visible focus and44px touch targets.
- CSV import/file/paste: explicit comma/semicolon/tab selector (no delimiter/locale guessing), UTF8 with optional BOM, exact address,amount,comment header and three fields per record. Quoted delimiters/newlines supported by pinned Papa Parse. Reject malformed CSV/headers/column counts, >200 records, >256KiB UTF8 and field limits atomically; report record number. Syntactically valid but semantically invalid fields may be applied and corrected in editor. Show preview rows/count, explicit append or replace action, never alter existing rows until apply. Reject appending beyond200. Replace requires explicit confirmation if list nonempty. Remote files and formulas never executed. Export UTF8 CSV with BOM and Papa escapeFormulae enabled, explain spreadsheet protection prefixes to preserve safety rather than promise byte-identical export.
- Demo button loads synthetic testnet addresses/amounts (explicitly marked, no observed user addresses). Confirm replacement of nonempty data. No payouts, fake on-chain statuses or assumed fee values.
- Preview shows full address/comment, per-row TON amount and exact total, testnet badge and read-only preparation notice. Network fee, service fee and signatures marked not yet calculated; no send/confirm-transaction action. These require stage3 chain/wallet capabilities; do not claim all of stage2 finished.
- Private draft editor uses identical recipient component and explicit save of name+recipients via existing PUT/version. Invalid unfinished recipients may be saved. Check encoded JSON64KiB request budget before save with current version/name. Existing401/logout, cancellation, identity isolation and CAS409 behavior preserved; conflict retains edits until explicit confirmed reload. Switching/opening a draft with unsaved changes also requires confirmation. Never report save success before response. No automatic save/offline writes.

## Implementation decisions left to builder

Use native controlled inputs; no form/global-store library is needed for three fields. Implement a small browser-native address decoder/checksum (not signing/crypto) from the official format, with golden vectors cross-checked using the backend's existing tonutils-go. No browser Buffer globals/polyfills. Papa Parse handles CSV syntax. Keep backend storage/OpenAPI unchanged: it intentionally stores unfinished text. Authoritative payout validation and matching Go monetary checks are stage3 work, before any signing. Local preparation is not authorization to send.

## Verification

Meaningful failing tests first: exact1nanoton/large sum, invalid formats/precision/range; friendly checksum/flags/raw strictness/canonical duplicates; malformed/quoted/BOM/formula CSV and limits; add/edit/remove, preview invalidation, duplicate acknowledgement, import append/replace; actual private recipients/version PUT,409 preservation and logout cleanup. Full npm check/audit; browser desktop/mobile widths and keyboard dialog focus using built app. One fresh whole-branch reviewer after implementation. User handles push/PR/merge; no worktrees or transfers.
