# Recipient editor review and verification

Stage2A adds native TON recipient preparation to the chosen mobile B workflow: mobile cards, desktop columns, detail dialogs and inline amounts. The same editor works in memory without login and in owner-isolated server drafts. CSV syntax is parsed locally with pinned Papa Parse5.7.0/types5.5.2; imports are staged and bounded, and replacements/deletions are explicit.

Amounts use BigInt nanotons, with no rounding, exponent or locale guessing. Address validation follows the public TEP2 byte format/checksum with strict raw input and canonical duplicate detection. Eight independent golden address vectors were generated by the existing Go tonutils library for both supported workchains, networks and bounce flags. This is preparation validation, not authoritative payout validation.

Observed TDD: pure input/CSV tests failed before modules existed; editor behavior failed before the component existed; edited-recipient draft tests failed before integration. Focused suites then passed. Private tests cover exact unfinished strings in versioned PUT, conflict retention, explicit reload/switch confirmation and logout during an outstanding write. Public tests verify no upload/storage during preparation and explicit authenticated save.

Independent builder check found no important unanswered design questions. Fresh whole-branch review found one Important stale-save-status issue and one focus issue originally graded Minor. The latter was regraded Important for keyboard users deleting deep in a200-row list: losing focus to the document start prevents predictable continuation. Both were fixed in one pass with observed failing regression tests: a pending public save now freezes the submitted list, successful status is tied to the exact snapshot and cleared on edits, repeat creation of the same snapshot is disabled, and deletion restores focus to the connected add button.

Full npm check passes93 tests; npm audit reports zero known vulnerabilities at verification. Real Edge production-build checks cover360/390/768/1280px without horizontal overflow, exact demo total, native file input CSV import/append, duplicates, preview invalidation, dialog keyboard trap/return focus and zero runtime exceptions. Screenshots were inspected. Browser API/auth in this local static preview is unavailable; real saved-draft HTTP behavior is covered by the existing production service and component API tests, not claimed as a new real-wallet device test.

Backend and public OpenAPI remain unchanged because the existing API already accepts unfinished recipient strings. Network/service fees, balance, actual maxMessages/signature plan and matching authoritative Go payout validation remain before stage3 signing. Nothing here sends funds. The existing SDK chunk-size warning remains. No push, merge or feature deployment performed.
